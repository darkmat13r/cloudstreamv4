# I18N — strings and localisation

The strings pipeline is built and merged. What remains is adoption, hardcoded English, and defects
in the translation data itself.

**Direction, settled (reversed):** Compose resources are the **authored source**; `app/src/main/res`
is regenerated from them. The instruction is that all strings are Compose resources with no Weblate.
This replaces the earlier "generated from `app/src/main/res`" direction, whose stated reason was
wrong: the "61 corrupted values" was a property of translate-toolkit (Weblate's reader — its
`CMPResourceUnit` overrides only writing, while reading keeps Android semantics), never of the CMP
format. This repo is not connected to that Weblate project in any case (see `I18N-05`). Plan and
progress: `I18N-07`.

## I18N-01 — `UiText` → `UiString` adoption

**Status:** open · **Size:** many small PRs

`utils.UiText` / `txt()` are `@Deprecated(WARNING)`. The last measured count was **268 deprecation
warnings** in `:app:compileStableDebugKotlin`.

- [ ] Write the `UiText` ↔ `UiString` adapter — it does not exist yet, and without it every call
      site must migrate in one step
- [ ] Migrate by area, smallest first
- [ ] Only then raise the deprecation to `ERROR`

**Trap:** `UiText.asString` used `String.format` with the platform locale. `UiStringFormat` now
does too (#23), so a migrated call site renders identically — but that was only true from #23
onward. Anything migrated before it silently changed what German and Arabic users saw.

## I18N-02 — Hardcoded English time units

**Status:** open · **Size:** one PR, but it touches a published ABI

`AccountManager.secondsToReadable` emits `d`, `h`, `m` — and now `s` (#26) — as hardcoded English
letters, in a function that is on the **published extension surface**
(`app/api/classes-jar.api:16463`).

Meanwhile the app already owns fully translated equivalents:

| Resource | Format | Locale files |
|---|---|---|
| `duration_format` | `%d min` | **61** |
| `next_episode_time_hour_format` | `%1$dh %2$dm` | **60** |
| `download_time_left_hour_min_sec_format` | `%1$dh %2$dm %3$ds` | 42 |

Real translations: `ru` `%1$dч %2$dм`, `ja` `%1$d時間%2$d分`, `ar` `%1$d ساعة %2$d دقيقة`.

- [ ] Fix the display call sites first — see `I18N-03`, which is the first of them
- [ ] Only then consider `secondsToReadable` itself; changing what it returns is visible to
      third-party extensions, and it is used for "remaining" where seconds matter

## I18N-03 — Result page renders runtime in hardcoded English

**Status:** in progress

`ResultViewModel2.kt:345` renders `2h 22m` through `secondsToReadable`; the home preview
(`HomeParentItemAdapterPreview.kt:372`) renders the same film's runtime as `142 min` through the
**translated** `duration_format`. So the two disagree, and the result page is the one emitting
English.

Fixing it via the existing resources **gains** translations in ~60 locales and adds no new
translatable string.

**Trap that shapes the fix:** `apc` renders `duration_format` as `دقايق: %d` — **number last**. Any
design that concatenates two separately formatted pieces produces garbage there. The positional
resource has to be used whole.

## I18N-05 — Broken translations, and who owns them now

**Status:** open · **Ours to fix** — see below

### The mechanism, because it is not what it looks like

`README.md:109` links a Weblate project at `hosted.weblate.org/engage/cloudstream/`, and this
repo's history carries **97 commits** titled `Translated using Weblate (<Language>)`, the most
recent dated 2026-08-26. `.github/workflows/strings_guards.yml:3` records why that matters:

> Translations reach master by push (Weblate, then `update_locales.yml`), where
> `pull_request.yml` never runs.

That is the entire reason `strings_guards.yml` exists — translation pushes bypassed PR review, so
the content guards had to run on push instead.

**But that was upstream.** This repo's only remote is `darkmat13r/cloudstreamv4`, and it is not
connected to that Weblate project (see `DEC-03`: separate private repo, not a fork). No bot pushes
here. The 61 locale files are a **frozen snapshot** inherited at fork time.

Two consequences, and both invert the usual advice:

- Reporting these upstream would only help upstream's users. A fix there never reaches this repo.
- **These files can be edited directly.** There is no sync to overwrite the change.

Note also that Weblate validates *placeholders* automatically, which is exactly why the defects
below survived: `%1$dd` contains a structurally valid `%1$d`, and Hebrew `חודשים` is a well-formed
word in the wrong place. No automated check catches either.

### `duration_format` — junk values

| File | Value | Note |
|---|---|---|
| `values-b+lv` | `%d galvenais` | Latvian for "main". If `lv` reaches a user, a 142-minute film reads "142 main" |
| `values-b+so` | `%d dqq` | |
| `values-b+qt` | `%d ooaaaugha` | `qt` is a pseudo-locale, and one of the three with no CLDR plural rules |

Live on the result page as of the runtime change, and on the home preview already.

### `next_episode_time_hour_format` — wrong values

Currently visible only in the "next episode airs in" countdown. They are **not** on the result
page, because the runtime change deliberately uses one resource at every magnitude.

| File | Value | 142 min renders as |
|---|---|---|
| `values-b+my` | `%1$ddနာရီ %2$ddမိနစ်` | `2dနာရီ 22dမိနစ်` — stray Latin `d` after each number |
| `values-b+so` | `%1$ds %2$dd` | `2s 22d` — reads as seconds and days |
| `values-b+iw` | `%1$dשעות %2$dחודשים` | "2 hours 22 **months**" |

- [ ] Decide per string: fix in place, or drop the translation so the locale falls back to English
      (English is better than "22 months")
- [ ] `qt` may not be worth fixing at all — establish whether it is a real target

## I18N-06 — Platform actuals for `NumberSymbols` are untested

**Status:** open · low priority

`UiStringFormat` reads locale digits and separators through an `expect`/`actual`. The JVM actual is
covered by 35 tests. The **android** and **ios** actuals are argued-by-construction, not measured:

- `:core:strings` has no Android unit-test target, and Android's locale data is ICU-backed rather
  than the JDK's CLDR, so a locale whose ICU `zeroDigit` or `groupingSize` differs would diverge
  silently.
- The iOS actual compiles (both klib targets, clean) but nothing checks that `ar` on iOS produces
  the same digits as `ar` on Android.

- [ ] Cheapest fix if it ever matters: run the same symbol table the JVM test pins, on device

## I18N-07 — The strings flip: Compose resources become the source

**Status:** open · steps 0–2 `done` (#32), step 3 in progress on `feat/strings-source`, steps 4–5 not started · **Size:** six PRs, each revertible

Reverses the direction `I18N-M1` built. Only step 4 changes a shipped byte. Everything below was run
locally, not in CI (see `INF-01`, `DEC-01`).

- [x] **PR 0 — freeze the baseline.** `done`, #32. `core/strings/oracle-baseline/` holds the six
      files `stringsOracle` produces, captured pre-flip: `decoded.tsv` 32,649 rows; `emitted.tsv`
      34,561; `lookup.tsv` 66,315; `requests.tsv` 87; `findings.tsv` 65; `report.txt` 13 lines.
      `OracleBaselineTest` compares them.
- [x] **PR 1 — the encoder.** `done`, #32.
      `build-logic/convention/src/main/kotlin/strings/AndroidStringsXml.kt` writes every value
      quoted. Inside `"…"` aapt2 does not trim whitespace, does not read a leading `@`/`?` as a
      reference, and accepts a bare apostrophe, which is what makes the encoder total. The corpus's
      363 apostrophes need no rule at all.
- [x] **PR 2 — the round trip.** `done`, #32. `verifyStringsRoundTrip` re-encodes all 62
      directories, recompiles with the same aapt2, reads every value back and re-runs the forward
      generator. Measured: `second pass: emitted values by reason: {OWN=33105}` (zero
      `REFERENCE_IN_LOCALE`, zero `ANDROID_FALLBACK`) and `lookup diff against the frozen baseline:
      0 lines (66315 baseline cells, 66315 round-trip cells)`.
      Two guard cases: `android-encoder-roundtrip` (a slice of six real res directories) and
      `android-encoder-rules` (27 synthetic values). Mutation-testing each of the 8 encoder branches
      individually: the corpus slice alone guards 2 of 8; the synthetic case brings it to 5 of 8.
      The remaining 3 (`>`, LF, TAB) **cannot** be caught by a round trip — a bare `>` is
      well-formed XML character data, and inside quotes a literal newline or tab decodes back
      unchanged. Those three buy file shape, not value fidelity; what they protect against is AGP's
      resource merger, which the harness does not run.
- [ ] **PR 3 — move the source.** `in progress` (branch `feat/strings-source`). The authored tree is
      committed at `core/strings/src/commonMain/composeResources/`: 62 directories, 33,100
      resources, 2,500,708 bytes, a verbatim byte-for-byte copy of what `generateComposeStrings`
      emits minus `values-b+he` and `values-b+id`. A new `materialiseComposeStrings` task adds those
      two back as byte copies of `values-b+iw` / `values-b+in` and feeds
      `compose.resources.customDirectory`. `app/src/main/res` is untouched.
      Corroboration: 33,100 committed resources + the 5 of `authored-additions.tsv` = 33,105, which
      is exactly the `expectedOwn` the round-trip task pins.
- [ ] **PR 4 — the flip.** `open`. Regenerates `app/src/main/res` from the authored tree. **The
      first step that changes a shipped byte.** The 5 values of
      `core/strings/authored-additions.tsv` are folded into the authored tree here: they are
      base-only `@string/` aliases in `values-b+tl` and `values-b+zh+TW` that Android re-resolves
      per locale, and flattening the alias without them regresses Traditional Chinese to English.
      `oracle-baseline/emitted.tsv` and `report.txt` need one reviewed update here; `lookup.tsv`
      must stay at a zero-line diff.

      **Surveyed at `1254d2bd`**, by diffing `build/stringsRoundTrip/res` against the committed
      res. What the regeneration does, measured rather than assumed:

      | | |
      |---|---|
      | keys **removed** | **0** — nothing is lost (a first pass said 27, which was a regex counting commented-out `<string>` lines; corrected) |
      | keys **added** | **725** across 61 dirs — materialised fallback copies, all values Android already resolves identically (`lookup diff: 0 lines`) |
      | base `values/strings.xml` | 736 → 758 keys; the +22 are exactly the visible `donottranslate` names, so deleting those 22 is **mandatory**, and is also sufficient — no other collision |
      | total bytes | 2,632,333 → 2,621,037, i.e. **−11,296** — dropping comments and `formatted="true"` more than pays for the 725 copies |
      | comments destroyed | **172** in 23 dirs (127 instructional, 45 commented-out resources) — recovered first into `docs/strings-translator-notes.md` |
      | `<b>` flattened | `device_pin_url_message` in 34 locales, the corpus's **only** styled string — accepted, decided 2026-10-03 |
      | `formatted=` | 2,293 occurrences, **all `"true"`** — none is `"false"`, so verify dropping it is behaviourally neutral before relying on it |
      | element types | only `<string>`, `<plurals>`/`<item>`, `<resources>`, `<b>` — no string-arrays, no xliff, no `translatable="false"` |
      | `values-arz` | the one res dir with no emitted values; it has no counterpart in the authored tree |
- [ ] **PR 5 — retire the Weblate machinery.** `open`. Delete the empty `values-arz` while pinning
      `arz` in `parity-requests.txt`; delete `.github/workflows/strings_guards.yml`; delete the 22
      duplicate `donottranslate` names; add a DOCTYPE guard in front of Compose Multiplatform's
      unhardened `DocumentBuilderFactory`.

**Settled decisions of this plan:**

- Delete the 22 duplicate `donottranslate` names.
- Accept `<b>` flattening and alias flattening.
- Keep `formatted="true"`.
- Always-quote encoding.
- Commit the generated `res`.
