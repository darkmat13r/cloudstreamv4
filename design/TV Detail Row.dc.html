Settled, and the contradiction this board used to carry is gone. One reading to confirm. Rule 4 says a toggle "with no such pair yet keeps today's raised fill for on until its pair is named here". The watchlist's pair is named, so this board takes the fill away and lets shape carry state alone — otherwise state would be said twice, once of them by the 1.15:1 the decision just removed. The first choice was an outline bookmark against a filled one. The skeleton's action bar has to be re-derived per type, and that is new. On 7a the loading skeleton drew one action bar from x200 to x1440 because the row was three text buttons and two cells and ended there. These rows do not: 7f ends at x1104 (552 dp) and 7g at x1344 (672 dp), measured to the last visible tile edge rather than the 96 cell edge, because the tile is the ink. The skeleton cannot know the type before the title resolves, so either it draws the shorter of the two and a film's row grows on arrival, or the bar stops being one bar and becomes the primary's 440 plus a cell-sized box per action. Drawing the shorter bar and letting it grow is the smaller jump and is what this set assumes, but it is still a jump and the owner may prefer the second. Today's built page has the same fault in a different place — the skeleton's bar runs to 1076 px against the loaded row's 1030 px at 1280 wide, a 46 px jump nobody drew.

Header order: count · provider, everywhere. The boards are inconsistent — Cast reads "38 · TMDB" in three places and More like this reads "HDREZKA · 24" in one. With count first that degrades to "38" with the same element leading; with provider first the leading element changes when attribution is missing. 7i therefore reads "Episodes 24 · HDREZKA".
