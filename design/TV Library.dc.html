Re-cut twice after measuring computed boxes rather than declared CSS. The declared-value scanner passed this file. Measuring where elements land found the five systemic causes listed in Search; extending the measurement to text boxes found a sixth, because the first pass only looked at painted elements.

A text stack must total a multiple of 16 to centre in a 96-tall row. Title 32 plus a 4px gap plus subtitle 24 is 60, which centres at +18 — so every line of every list row and every chrome button sat off the step. The gap is 8, the stack is 64, the offset is 16. A single line centred alone needs a 48px line box to land at +24. And an inline <span> reports its ink box rather than its line box, so reveal text is display: block.

Then a stricter scanner found 156 more, the worst of any file — and they were four mistakes, not 156. Every one was a small box centred inside a bigger one, which is the single most productive way to turn two on-grid values into an off-grid position. The tab count was a 24 line box in a 48 pill (+12). The badge was a 24 line box in a 32 chip (+4). The sort-direction label was a 24 box in a 48 cell (+12). The card’s progress rule was 4px at the card’s bottom edge, putting its own top at a fraction. Every line box that sits in a 48 or 32 cell is now 32, and the rule is 8. The general fix is never to nudge the offset: make the child’s box equal the parent’s, so there is no offset to be wrong.

Only the bound badges were wrong. The literal ones — CACHED, typed into the markup — measured clean, and the interpolated ones did not, because a literal is an inline text node whose rect is a font metric while {{ value }} is wrapped in a block that takes a real box and gets centred. A mockup measured only with literal content has not been measured.

The line-box ramp, measured rather than estimated. The earlier “about 1.3×” rule was an estimate applied to both families at once, and that was the bug. Measured ink is Manrope 1.30× the size at its heaviest weight and JetBrains Mono 1.182×, which is why the same 20px size needs a 32 box in the sans and fits 24 in the mono. Read the box from §03’s table; never derive it from a ratio. Note also that the browser’s content box is larger than the ink and that a line box smaller than it is harmless — Manrope 24/32 measures 33 of content box and does not clip, and “fixing” it to 40 would add 8px to every card title in the app.

Two rows and a peek. Grid pitch is 320 — rows at 304 and 624 inside the band, a third at 944 crossing it. A row below the fold is the one legitimate exception to “no focusable crosses y1024”, because reaching it scrolls the grid and puts it back inside the band; the verifier allows exactly one such row.

And one defect that no amount of geometry measurement could find. This file measured 0 off-grid, 0 clipped and 0 band violations while setting --mut to #686868 — 3.17:1 against the raised fill it sits on in every chrome button, against a 4.5:1 AA floor. It carries the provider name, the sync age, the sort criterion and every list row’s second line. It is now #858585, 4.78:1 on raised and 5.69 on black. A colour moves no boxes, so it passed every scanner ever pointed at this file. See §08 of the design system.

Three engineering prerequisites this cluster adds to the register in Components.dc.html: a typed failure on the library resource carrying which provider failed and why (today it is Resource.Failure(false, "Unable to fetch library") and the TV branch drops it); a lastSyncedUnixTime per provider so “CACHED 2H” is a fact rather than a guess; and per-page counts on SyncAPI.Page so a tab can carry its number without loading the page.
