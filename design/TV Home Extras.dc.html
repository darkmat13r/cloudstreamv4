The owner’s rulings, 2026-11-05, and what changed for them

1 · Details panel: hold OK, plus the Menu key, as drawn. 2 · Random is not a Home source. It is gone from 3h, and None alone remains beside the real sources. The Random button stays in the chrome, always shown, and opens a random title. 3 · Search is in the top bar only. It is gone from the details panel and from cards. 4 · A failed reload shows the error page, now 3m, not the kept rows. 5 · Subscribe is in 3k, inside the band, and 3l matches. 6 · The token wins for list rows (16) and rings (4 at 4, on the visible control). 7 · White means focus only, so 3j’s Resume is no longer white at rest.

How a remote reaches the details panel (3k)

Hold OK on a card, as the old TV page did (SearchResultBuilder.kt:231), or the Menu key where a remote has one. No card gains a stop, so RIGHT still walks the cards. On a remote that delivers neither, OK still opens the title’s page, which carries the details and the bookmark (7a). The hint on 3e names the gesture, and names Menu only where KeyCharacterMap.deviceHasKey says it is there. Not measured: which remotes fail to hold OK. That needs real hardware.

What the measuring caught

The scanner’s first run said zero, and it was wrong. Bound text sits in an inline span, so the scanner counted no text boxes at all. Moving a box, clipping a label and colliding the notice with the source control on purpose showed it: two of those went unreported. With text counted it found one real fault, a synopsis clamped at two lines and cut off. It also flagged mono 20/24 for a content box of 25, which Design System v2 §03 says does not clip, so vertical clipping now tests the measured ink. Every ring was then read again from the pixels: gap and stroke on all four sides.

Where these boards clash with others, for the owner

Primary at rest. Components draws the primary button white at rest (.btn.pri, “Primary is white fill, black label”), and so do 3c and StateActionButton. Under “white means focus only” 3j draws it at rest as a raised fill with an ink label in 800 and a muted hairline, so it still outranks the secondaries, whose labels are ink2. This is an invention, not a Components state, and 3c, Components and the built button all still say white. The focused primary on 3g and 3m is white with the ring, as Components draws it. Error with local rows. 3g keeps the bookmarks rail offline; 3m, as ruled, shows the error page alone. If Continue watching or bookmarks should stay above it as on 3g, that is one more ruling. Random “always shown”. Read as: no setting in front of it. With nothing loaded it has nothing to pick from, so 3g, 3i and 3m leave it out. If it should show there too, it needs a rule for what it does. Icon rings. The ring sits on the 48 tile; Compose’s IconCell has no tile and rings its cell, which DS-12 left unruled. List rows are 16, which other boards still draw at 8. Continue draws four cards so none crosses the band. Line references to feature/home and cloudstream4/home files (HomeContracts, HomeMvi, HomeCopy, HomeScreenTv, HomeRailTv, HomeSourcePanelTv, DataStoreHomeSourceMemory) are PR #147 at 5921e6942. A bare HomeViewModel.kt, and the other old-app files, are :app on master.
