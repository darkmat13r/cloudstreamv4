What measuring computed boxes found that measuring declared CSS did not. The first scanner read every px value in the stylesheet and passed this file clean. Re-measuring where elements actually land found 35 off-grid boxes; extending that to text boxes found 15 more. Six causes, all systemic:

1 · A 1px border consumes layout. It shifts the padding box by 1, so the glyph inside the search field landed at x225 and the 560 panel became 561 wide at x1359. Every hairline is now box-shadow: inset 0 0 0 1px, which paints without occupying space.

2 · A transparent border is not a focus ring. border: 4px solid transparent pushed the card’s badge to x212 and its progress bar to x204. The ring is an outline, so the art box is exactly 160×240.

3 · The lift was 12. Every focused card sat off the step. The lift is 8, so a lifting row sits 32px below what precedes it — 24 of clearance plus the 8 it rises. Rail pitch 352: header 296…352, cards 384…624, next header 648…704, its cards 736…976.

4 · Centring an odd size in an even cell. A 40-tall chip in a 96 cell lands at 204; a 24px glyph lands at x92. The chip visual is 48 and glyphs are 32 — both centre onto the step, and both read better at ten feet.

5 · A text stack must total a multiple of 16 to centre in a 96 row. Title 32 plus a 4px gap plus subtitle 24 is 60, which centres at +18 — so every line of every list row was off the step. The gap is 8, the stack is 64, the offset is 16. A single line centred alone needs a 48px line box, not 40, to land at +24.

6 · Intrinsic widths are exempt, and the contract now says so. A chip’s width comes from its string, as does the x of every chip after it. In Compose that is wrapContentWidth in a Row with 24dp spacing — no engineer types those numbers, so the 4dp rule does not reach them. The grid governs every dimension a person writes and the origin and size of every fixed-size element, not text measurement.

And then a stricter scanner found sixteen more, plus a clipped run. The six above were real and the file still was not clean, because the scanner that found them was not strict enough. Four further causes, each now fixed here and in the contract:

7 · Baseline alignment cannot land on the step. The rail header was align-items: baseline, which put the mono count at y315 and y667 — the offset is whatever the two fonts’ baselines happen to differ by. Both children now carry the same 56 line box. Compose’s Alignment.Baseline has the identical defect; CenterVertically is what this actually is.

8 · Manrope 20 has no valid 24 box. The poster reveal title was 20/24 and inks 26.0 at weight 800. It is 20/32. The ramp had published 20/24 as a single caption rung, which was true of the mono at that size — mono inks 23.64 — and false of the sans. One ratio for two families was the bug, and it also reached :core:theme.

9 · A bound value and a literal do not lay out the same. The badge was a 24 line box in a 32 chip, so its text centred 4px off — but only where the text is bound. A literal is an inline text node whose rect is a font metric, not a layout box; an interpolation is wrapped in a block that takes a real box and gets centred. The literal badges measured clean and the bound ones did not. A chip’s line box is now its own height.

10 · A 4px rule is exempt in its own axis, not in where its edges land. The card’s progress rule sat at the card’s bottom edge, which put its own top at a fraction and would have done the same to anything stacked under it. It is 8.

11 · The muted token was below the contrast floor. --mut was #686868 — 3.77:1 on bg, 3.43 on surface, 3.17 on raised, against the 4.5:1 AA minimum for normal-size text. On this board it carries the provider meta on every list row, the timeout reason in the failure pill, the search placeholder and the “See all” count. It is now #858585: 5.69 / 5.18 / 4.78. Unlike the ten findings above, this one moves nothing — which is exactly why it survived ten passes of geometry measurement without being noticed.
