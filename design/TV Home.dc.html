One value cost ninety-nine boxes. The hero headline was 88px/0.94. A unitless line-height of 0.94 on 88px is 82.72, which is not an integer, let alone on the 8px step — and because the hero was laid out in normal flow, every band beneath it inherited the .72 and landed at 322.72, 382.72, 545.5. Nothing in the file was visibly wrong; every number in it was a round one. The hero bands are now placed absolutely, so a line box can never push the next band off the step again.

Then the ramp itself turned out to be measured wrong. The line boxes came from an estimate that Manrope's glyph box is about 1.3× the font size. A canvas probe of the actual font says 1.375× — and 1.30× for JetBrains Mono, which is why the two families need different boxes at the same size. The consequence is one real rung: Manrope 20 measures 25.76 of ink and cannot live in a 24 box at all. The poster reveal title moves to 20/32. An estimate that is right to within 6% is still wrong at every size where the rounding lands on the other side of a step, and the only way to know which sizes those are is to measure them.

A bound value and a literal one do not lay out the same. The last four off-grid boxes were all badges — NEW, 4K, DUB — and only the bound ones. A literal string is an inline text node whose rect is a font metric, not a layout box, so nothing measures it and nothing can put it off the step. An interpolated value is wrapped in a block element, which takes a real box, and a 24px box centred in a 32px chip sits 4px off. The same chip was correct with the text typed in and wrong with the text bound. Every chip's line box now equals its own height, so the text fills the chip instead of being centred inside it — and the wider lesson is that a mockup measured only with literal content has not been measured.

A 4px progress rule broke the rhythm of everything under it. The continue card read art 216, gap 8, rule 4, gap 12, title — which put the title at 956 and the subtitle at 996, neither on the step. The rule is now 8px: a real 4dp dimension rather than a hairline exception, which makes the block art 216 + 8 + 8 + 8 + 32 + 8 + 24 = 304 and lands its bottom edge exactly on y1024. The same class of error produced the baseline-aligned rail header (mono count at y651), the 32px pager row (an 8px dot centred to y532), and a 4×4 separator dot centred in a 32px line (y374). Each is a small box centred inside a bigger one, and centring is how a value that is itself on the grid produces a position that is not.

The third rail is a peek, and that is a real loss worth naming. A poster rail block is 328 — a 56 header, the 32 of lift clearance, and 240 of card. Three of those plus their 24px gaps is 1032 against the band’s 968, so the third crosses y1024. The contract permits exactly one such row, and a row that is visibly cut is also the clearest possible scroll affordance. The alternatives were worse: poster-sm 128×192 makes the most prominent rail the smallest, and dropping to two rails wastes 200px of band. What changed is the clearance — at the old 8px gap three rails did fit, and that gap was wrong.

What the scanner does not check, and why. A shrink-to-fit width around text — a button, a chip, a certificate badge — cannot be on the grid, and neither can the x positions it induces in the elements after it in a flex run. That is wrapContentWidth with Arrangement.spacedBy, and constraining it would mean setting widths on labels, which is how text gets truncated in one locale and floats in another. A declared min-width is not a declared width — the label here is wider than the 240 the primary button asks for, so the content decides. A progress fill's percentage width is a continuous value, not a layout dimension. Strokes at or under 4px are hairlines. Everything else — every absolute origin, every declared width and height, every padding, gap and radius — is on the 8px step, and radii are only off it where a radius is a box's own half-height, which is the only way to draw a circle.

The muted token moved after this file was measured clean. --mut was #686868, which is 3.77:1 on this black — below the 4.5:1 AA floor for normal-size text, and it carries the source-and-quality line on every Continue card and the count on every rail header. It is now #858585: 5.69:1 on bg, 5.18 on surface, 4.78 on raised, and still far below ink2’s 13.08 so the hierarchy holds. A colour moves no boxes, so the geometry above is unaffected.
