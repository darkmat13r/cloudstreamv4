This cluster is the one that was already “solved”, and the solution failed verification 28 times. It is worth saying what that changes: a spec can be detailed, internally reasoned and still be unbuildable, and the way you find out is to check it against the contract element by element rather than read it. Four of the fourteen findings on the suggestions board alone were not geometry at all — they were claims the screen’s own evidence contradicted.

The status line and the rows have to agree, and they did not. The draft’s status line read “9 of 12 sources answered · 3 failed” — 9 + 3 = 12, so nothing is outstanding — while three rows showed “checking”, which the same draft defined as “its providers are outstanding”. Both cannot be true, and the error cascades: a title cannot be carried by nine providers if fewer than nine have answered. Here 12 are selected, 9 answered, 3 failed and 0 are outstanding, so every count on screen is final and the arithmetic closes.

One ranked column, because two columns caused the dedupe bug. The prerequisite mandates a case-insensitive collapse so a recent “dune” and a TMDB “Dune” become one row. The two-column draft drew both — dune at rank 1 with an empty count and Dune at rank 5 with seven sources — which is the exact pair the prerequisite names. It also proved the empty count was not a data limit, since the same fan-out produced a count for that very title. Row 1 here is the collapsed row: one query, both origins, one count. Row 5 shows an honest 0 sources — checked, nobody carries it — which is only sayable because nothing is outstanding.

Where a state’s action lives is a geometry decision, not a copy decision. The no-results draft put its button at x824–1240, y760–824. The whole region y272–1024 contained no other focusable: 488px of void above it, nothing below, and three of the six chips had no geometric DOWN target because they ended at x712 while the button started at x824. The button now rides the chip row. That single move also closes a hole the draft created elsewhere: the chip row ran x200–1416 and the Sources button spans x1440–1864, so DOWN from Sources landed on nothing at all — the “deliberately empty” 424px tail was the bug.

An action has to retry the thing that failed. The draft’s error state was “Couldn’t reach the suggestion service” and its only reachable action was “Retry 3 sources”, which retries providers — and which was hidden when no provider had failed, i.e. exactly when the suggestion service is the only thing down. The error state therefore had no action at all. There is now one slot in the chip row whose label is bound to what failed: “Retry 3 sources” on 8a, “Search all 12 sources” on 8b, “Search everything” on 8c. And 8c’s label names both halves of what it clears, because the binding (providersActive = emptySet(), types = emptyList()) discards the provider filter and the lit Movies chip, while the old label mentioned only providers.

Zero uses of live on all five boards. The draft spent it on a focusable button as a “failure marker” and then again to recolour a 472×32 text strip for the offline state — offline is a connectivity state, not playback and not failure, and a recoloured region is a wider use than a marker. §04’s own answer is a hollow muted glyph plus the reason in words, which is what the status pill carries.

The 128×72 thumbnail does not fit a 96 row, and the design system already said so. 96 − 2×16 = 64, and 64 < 72. The draft paid for it with asymmetric padding (16 top, 8 bottom), abandoning the chassis’s inner padding on one edge; centring was not available either, since (96 − 72)/2 = 12 and 12px is 6dp. Quick Search uses the chassis 48 disc, which fits with 24 above and below — and that also frees the horizontal budget for the type glyph the draft declared in its bindings and had no room to draw: 472 − 32 = 440, consumed exactly by 128 + 16 + 296.

A panel is its own coordinate space, and the band check is what proved it. Both Quick Search boards first drew their content at the correct artboard x — 1392 — but those elements are children of an absolutely positioned .panel, so 1392 was measured from the panel’s own left edge at x1360, and the entire panel contents rendered at x2752–3224: 832px off the side of the screen. Nothing else in the scan could have caught it. Every box was still the right size, still on the 8px step, still internally consistent; an off-grid or clipping check has no opinion about a panel that is not on the artboard. Only the focus band — which asserts an absolute position against x56–1864 — is stated in coordinates a containing-block mistake cannot satisfy.

The contrast finding this board raised is now fixed system-wide. The verifier flagged --mut #686868 as the least legible pairing here, and measuring it confirmed worse than reported: 3.77:1 on --bg, 3.43 on --surf, 3.17 on --raised, all below the 4.5:1 AA floor for normal-size text, which 20–24px (10–12sp) is. It was not local to this file — that token carries the secondary line of every list row in all seven drawn files. It is now #858585 everywhere: 5.69 / 5.18 / 4.78. See §08 of the design system for the full audit, including the two tokens that are deliberately below the line and are not text.

Two prerequisites this cluster adds. An Idle | Suggesting | Results enum cannot express this screen — it owes five states plus the row grid, so the render function has more surfaces than the enum has cases; it needs the same UiState the rest of the app uses. And the focus order for a streaming list is the result set, not the five viewport slots the draft enumerated: 12 answering sources produce more than five rows, two of which already come from the same provider, so DOWN from the last visible row scrolls, and only DOWN from the last result row reaches the pinned Done.
